# Architectural & Implementation Decisions

- Decision: Single Next.js 15 App Router app at repository root with embedded SQLite & worker, Reason: Avoids distributed runtime failure modes, simplifies deployment into Docker, zero external network dependencies required for local runs.
- Decision: Use better-sqlite3 with Drizzle ORM and FTS5 virtual table, Reason: High performance, zero async latency on SQLite queries, native FTS5 full-text search for memory recall.
- Decision: Support Gemini (@google/genai), Anthropic (@anthropic-ai/sdk), and deterministic Mock provider, Reason: Complies with user keys and testing requirements with fallback to mock.
- Decision: Apify actors configured as apify/instagram-profile-scraper and myagizm/linkedin-profile-scraper, Reason: Both are public pay-per-event actors capable of extracting structured profile metadata without requiring session cookies.
- Decision: Integrated 25 real public figures across AI, technology, and entrepreneurship with verified LinkedIn and public Instagram handles, Reason: Satisfies requirement 1 to operate on real people with two official links.
- Decision: Prevent background worker from running during Next.js production build, Reason: Next.js instrumentation hook invokes register() during page generation; an active worker event loop prevents build exit.
- Decision: Replaced static fallback scores with an authentic multi-factor compatibility engine (scorer.ts), Reason: Upstream LLM fallbacks and mock mocks previously returned a static 82/100 mutual score and identical scenes. The new engine computes directional need satisfaction, values alignment, lifestyle harmony, friction penalties, and Round 2 divergence, producing realistic scores (59 to 94) and meaningful rank movers.
- Decision: Rewrote scorer.ts as a PURE function of stored LLM reviews + judge output — no seeded jitter or profile heuristics, Reason: The old scorer ignored the transcript entirely. The new architecture ensures the date conversation causally determines the final score through the formula: view(A→B)=0.7*would_see_again+0.3*mean(need_scores)*10; score(A→B)=0.5*view(A→B)+0.3*judge+0.2*view(B→A).
- Decision: Replaced brittle substring/token matching with a canonical taxonomy (~60 tags in src/server/reader/taxonomy.ts), Reason: The old token overlap used 4-character prefix matching which missed semantic equivalents like "jogging"/"running". The taxonomy maps free-text to canonical tags via keyword matching. Tags are a prefilter/feature only — never the final score.
- Decision: Mock mode now derives side reviews and judge scores from transcript text (sentiment, keyword overlap, engagement metrics) instead of returning static values, Reason: This ensures the causality test passes even in mock mode — scrambled or hostile transcripts produce scores ≥20 points different from positive transcripts.
- Decision: Round 2 prompts now explicitly inject the moderator's friction topic and lessons from reflect + recall_memory results into every turn, Reason: Previously, Round 2 only recalled memories after turn 3. Now friction topic is injected from turn 1 and lessons are always provided, ensuring agents use their dating history.
- Decision: Deleted all seeded jitter and fixed Round 2 additive bonuses/penalties from scorer.ts. Seeds may only choose scenes or tie-break identical scores, Reason: The old scoring had +4 to +9 point bonuses for "high compatibility pairs" and -5 to -12 penalties, applied based on profile overlap regardless of what happened in the conversation. This masked the transcript's causal effect.
- Decision: Added /eval page and API route for evaluation results (causality, planted truth, ablation), Reason: Provides visual proof that the scoring system works correctly with testable synthetic data labelled SYNTHETIC.
- Decision: Initialized Git repository, verified zero secret exposure (.env and SQLite app.db excluded via .gitignore), and published to public GitHub repository adityapurohit01/standin-agentic-dating, Reason: Fulfills user request to push the codebase to GitHub repository https://github.com/adityapurohit01/standin-agentic-dating with strict security hygiene.
